## 💡 О проекте

**BUTION** решает главную проблему локального запуска современных ИИ-моделей: **нехватку оперативной памяти на одном устройстве**. 

Если 70B или 32B модель требует 24–40 ГБ RAM, а у вас есть, например, MacBook (16 ГБ) и Windows-ноутбук (16 ГБ), BUTION автоматически объединяет их в единый кластер. Веса модели прозрачно разделяются по сети, вычисления распараллеливаются через официальный `llama.cpp RPC`, а вы получаете полноценный стриминг ответов прямо в терминале.

> [!NOTE]
> Модель хранится **только на одном (основном) компьютере**. На второй компьютер GGUF-файл копировать не нужно — необходимые тензоры передаются на worker на лету по локальной сети.

---

## 🚀 Ключевые возможности

- 🔌 **Zero-Config обнаружение**: Узлы мгновенно находят друг друга в локальной сети через `mDNS / Bonjour` без ввода IP-адресов.
- 🔐 **Безопасное спаривание**: Защищённый канал управления на базе протокола `Noise_XX` с верификацией по 6-значному PIN-коду и привязкой по криптографическим ключам.
- 🧠 **Умный оптимизатор памяти (Tensor Split)**: Автоматический расчёт бюджета RAM каждого узла и подбор идеального соотношения разделения слоёв модели.
- 🌐 **Smart Multi-Route & Ethernet Turbo**: Измерение задержки и пропускной способности всех доступных интерфейсов в реальном времени. Автоматический выбор гигабитного Ethernet вместо Wi-Fi.
- 📦 **Установка в 1 клик**: Готовые скрипты установки для macOS и Windows с красивым CLI-интерфейсом, автоматической загрузкой `llama.cpp` и настройкой Firewall.
- 🖥 **Терминальный TUI-интерфейс**: Полноэкранный мониторинг на базе `Ratatui`: спидометр токенов (tok/s), графики сети, телеметрия RAM/CPU и встроенный чат.

## 📥 Быстрая установка

### 🍏 macOS (Apple Silicon / Intel)
Откройте Terminal и выполните команду:
```bash
curl -fsSL https://raw.githubusercontent.com/danytebyya/bution/main/install.sh | bash
```

### 🪟 Windows (x64)
Откройте PowerShell и выполните команду:
```powershell
irm https://raw.githubusercontent.com/danytebyya/bution/main/install.ps1 | iex
```

*Установщик сам скачает актуальные бинарники BUTION и `llama.cpp`, пропишет команду `bution` в `PATH` и настроит правила Windows Firewall для частной сети.*

## 🏁 Быстрый старт за 3 шага

```text
 ┌───────────────────────────┐         mDNS / Noise XX        ┌───────────────────────────┐
 │   Дополнительный узел     │ <────────────────────────────> │     Основной узел (Main)  │
 │      (Worker, 16 GB)      │      RPC Tensor Streaming      │   (MacBook / PC, 16 GB)   │
 └───────────────────────────┘ <════════════════════════════> └─────────────┬─────────────┘
                                                                            │
                                                                   GGUF Model (24 GB)
```

### Шаг 1. Подключите устройства к одной сети
Подключите оба компьютера к одному Wi-Fi роутеру, точке доступа смартфона или напрямую соедините их Ethernet-кабелем.

### Шаг 2. Запустите Worker (дополнительный узел)
На втором компьютере просто выполните команду:
```bash
bution
```

### Шаг 3. Запустите Main (основной компьютер с моделью)
На основном компьютере передайте путь к вашей GGUF-модели:
```bash
# macOS / Linux
bution --model "/path/to/model.gguf"

# Windows
bution --model "D:\Models\model.gguf"
```

1. На обоих экранах появится окно **Pairing** — сверьте код подтверждения и нажмите **Accept** (`Enter`).
2. Дождитесь завершения теста сети на вкладке `Benchmark`.
3. Перейдите на экран `Cluster` и нажмите `Enter` для запуска.
4. Откройте вкладку `Chat` и общайтесь с моделью!

## ⚡ Прямое соединение через Ethernet-кабель

Для максимальной скорости генерации токенов рекомендуется соединить два компьютера обычным кабелем Ethernet (или через переходник Type-C / Thunderbolt), оставив Wi-Fi для выхода в интернет.

BUTION автоматически протестирует оба соединения и перенаправит тяжёлый трафик тензоров через высокоскоростной кабель.

> [!TIP]
> Если IP-адреса для прямого Ethernet-подключения не назначились автоматически:
> - **Первый компьютер**: IP `192.168.50.1`, маска `255.255.255.0`
> - **Второй компьютер**: IP `192.168.50.2`, маска `255.255.255.0`
> - Поля *Шлюз (Gateway)* и *DNS* оставьте **пустыми**.

## ⌨️ Управление в TUI

| Клавиша | Назначение |
|:---|:---|
| `←` / `→` | Переключение между экранами (`Cluster`, `Nodes`, `Model`, `Benchmark`, `Chat`, `Settings`) |
| `↑` / `↓` | Навигация по спискам и элементам |
| `Enter` | Запуск / остановка модели, отправка сообщения в чат, подтверждение действия |

| `Space` | Переключение режима роли (`Automatic` / `Main` / `Worker`) |

| `Ctrl + L` | Очистить историю сообщений |
| `Q` | Выход из BUTION и корректная остановка всех фоновых процессов |

## 🛡 Безопасность и используемые порты

BUTION спроектирован для работы исключительно в доверенных частных сетях:

| Порт | Протокол | Назначение |
|:---|:---|:---|
| `5353` | **UDP** | Обнаружение узлов через mDNS / Bonjour |
| `31750` | **TCP** | Зашифрованный управляющий канал BUTION (Noise XX) |
| `31751` | **TCP** | Временный бенчмарк скорости сети (открывается только после авторизации) |
| `50052` | **TCP** | Передача тензоров `llama.cpp RPC` (привязывается строго к локальному IP) |
| `8080` | **TCP** | HTTP API модели (слушает **только** локальный `127.0.0.1` на Main) |

- Управляющий трафик защищён шифрованием `Noise_XX_25519_ChaChaPoly_BLAKE2s`.
- Доступ к удалённым RPC-воркерам разрешается только после ручного подтверждения на обоих экранах.
- BUTION не требует прав администратора в процессе обычной работы.

## 🔄 Обновление

Для принудительного обновления BUTION и `llama.cpp` до актуальных версий:

**macOS:**
```bash
curl -fsSL https://raw.githubusercontent.com/danytebyya/bution/main/install.sh | BUTION_FORCE_UPDATE=1 bash
```

**Windows:**
```powershell
$env:BUTION_FORCE_UPDATE="1"; irm https://raw.githubusercontent.com/danytebyya/bution/main/install.ps1 | iex
```

## 🛠 Разработка и сборка из исходников

Для локальной разработки и тестирования потребуется [Rust 1.80+](https://rustup.rs/):

```bash
# Клонирование репозитория
git clone https://github.com/danytebyya/bution.git
cd bution

# Проверка форматирования и линтеров
cargo fmt --check
cargo clippy --all-targets -- -D warnings

# Запуск тестов
cargo test

# Сборка оптимизированного бинарника
cargo build --release
```
